## 1. 版本概述

v0.7.0 聚焦于两个方向：**认知智能**（让 Agent 更"记得住"）和**生产就绪**（让 Agent 更稳定可靠）。

### 核心新增

| 模块 | 文件 | 对标 |
|------|------|------|
| 三层认知记忆 | `core/memory/cognitive/` | LangMem SDK |
| 统一 Agent API | `core/agents/create_agent.go` | LangChain 1.0 `create_agent` |
| 节点级缓存 | `graph/node/cache.go` | LangGraph Node-Level Caching |
| 延迟节点 | `graph/node/deferred.go` | LangGraph Deferred Nodes |
| Pre/Post Hooks | `core/middleware/hooks.go` | LangGraph Model Hooks |
| 可恢复流 | `graph/streaming/resumable.go` | LangGraph Resumable Streams |
| Trustcall | `core/output/trustcall.go` | Python Trustcall |
| Circuit Breaker | `core/agents/circuit_breaker.go` | 生产容错标准模式 |
| LangGraph Store | `graph/store/` | LangGraph Store |

### 向后兼容

v0.7.0 所有新增均为**扩展**，无破坏性变更，现有代码零迁移成本。

## 2. 三层认知记忆系统

### 2.1 架构概述

```
                    用户对话
                       │
                       ▼ AutoConsolidate()
         ┌─────────────────────────────────┐
         │        MemoryManager            │
         │  ┌──────────┐  ┌──────────┐  ┌──────────┐ │
         │  │  语义记忆 │  │  情节记忆 │  │  程序记忆 │ │
         │  │ 事实知识  │  │ 对话历史  │  │ 行为规则  │ │
         │  └──────────┘  └──────────┘  └──────────┘ │
         └─────────────────────────────────┘
                       │
                       ▼ Recall(query)
              AugmentedContext → System Prompt
```

### 2.2 快速开始

```go
import cogmem "github.com/zhucl121/langchain-go/core/memory/cognitive"

manager := cogmem.NewMemoryManager(cogmem.ManagerConfig{
    UserID: "user-alice",
    // 使用内置内存存储（开发/测试）
    SemanticStorage:   cogmem.NewInMemorySemanticStorage(),
    EpisodicStorage:   cogmem.NewInMemoryEpisodicStorage(),
    ProceduralStorage: cogmem.NewInMemoryProceduralStorage(),
    // 可选：自定义记忆提取器
    Extractor: cogmem.NewRuleBasedExtractor(),
})
```

### 2.3 语义记忆（Semantic Memory）

存储事实性知识，如用户偏好、领域知识、用户画像。

```go
// 手动存储
err := manager.StoreSemanticMemory(ctx, &cogmem.SemanticMemory{
    Content:    "用户偏好 Go 语言，有 5 年开发经验",
    Category:   "user-profile",   // preference / fact / knowledge / user-profile
    Confidence: 0.9,              // 置信度 [0,1]
    Source:     "onboarding",     // 来源标识
    // 可选：知识三元组（便于图谱构建）
    Triplets: []cogmem.KnowledgeTriplet{
        {Subject: "用户", Predicate: "偏好", Object: "Go 语言", Confidence: 0.9},
    },
})

// 关键词搜索
results, err := manager.SearchSemanticMemory(ctx, "Go 编程偏好", 5)
for _, r := range results {
    fmt.Printf("[%.2f] %s\n", r.Confidence, r.Content)
}
```

### 2.4 情节记忆（Episodic Memory）

存储完整对话片段，可用作 Few-Shot 示例。

```go
// 存储一段对话
err := manager.StoreEpisode(ctx, &cogmem.Episode{
    ThreadID: "session-001",
    Summary:  "讨论了 Go 并发模式",
    Messages: []types.Message{
        {Role: types.RoleUser,      Content: "Go 的并发怎么写？"},
        {Role: types.RoleAssistant, Content: "使用 goroutine + channel..."},
    },
    Tags:    []string{"golang", "concurrency"},
    Quality: 0.9,       // 质量分（用于 Few-Shot 筛选）
    IsFewShot: true,    // 标记为 Few-Shot 示例
})

// 搜索相似情节
episodes, _ := manager.SearchEpisodes(ctx, "Go 并发编程", 3)
```

### 2.5 程序记忆（Procedural Memory）

从反馈中学习行为规则，自动优化 Agent 响应风格。

```go
// 正向反馈（强化成功行为）
manager.UpdateProceduralMemory(ctx, &cogmem.Feedback{
    Score:   1.0,
    Comment: "用户对详细的代码示例满意",
})

// 负向反馈（学习改进点）
manager.UpdateProceduralMemory(ctx, &cogmem.Feedback{
    Score:         -0.5,
    FailureReason: "回答过于冗长",
    Comment:       "用户希望更简洁",
})

// 获取学习到的行为规则
procMem, _ := manager.GetProceduralMemory(ctx)
for _, rule := range procMem.BehaviorRules {
    fmt.Println(rule.Rule) // 提取到的行为模式
}
```

### 2.6 统一检索 Recall

**核心功能**：并行搜索三层记忆，生成可直接注入 System Prompt 的增强上下文。

```go
opts := cogmem.DefaultRecallOptions()
opts.K = 5             // 每层最多返回 5 条
opts.MinConfidence = 0.5  // 过滤置信度低于 0.5 的记忆

recalled, err := manager.Recall(ctx, "用户的 Go 编程偏好", opts)

// recalled.SemanticFacts   - 语义记忆结果
// recalled.RecentEpisodes  - 情节记忆结果
// recalled.ProceduralHints - 程序记忆提示

// AugmentedContext 可直接使用
systemPrompt := "你是一个专业助手。\n\n" + recalled.AugmentedContext
messages := []types.Message{
    {Role: types.RoleSystem, Content: systemPrompt},
    {Role: types.RoleUser,   Content: userInput},
}
```

### 2.7 AutoConsolidate（自动记忆提取）

从对话历史中自动提取并存储到三层记忆，无需手动分析。

```go
// 同步模式（等待提取完成）
err := manager.AutoConsolidate(ctx, messages)

// 异步模式（不阻塞主流程，适合生产）
manager2 := cogmem.NewMemoryManager(cogmem.ManagerConfig{
    UserID:               "user-123",
    AutoConsolidateAsync: true,
    // ...
})
```

### 2.8 生产存储后端

实现 `SemanticStorage` / `EpisodicStorage` / `ProceduralStorage` 接口，即可接入 PostgreSQL、Redis 等：

```go
type MyPostgresSemanticStorage struct {
    db *pgx.Pool
}

func (s *MyPostgresSemanticStorage) Save(ctx context.Context, mem *cogmem.SemanticMemory) error {
    _, err := s.db.Exec(ctx, 
        "INSERT INTO semantic_memories(id, user_id, content, confidence) VALUES ($1,$2,$3,$4)",
        mem.ID, mem.UserID, mem.Content, mem.Confidence)
    return err
}
// ... 实现其余接口方法
```

## 3. 统一 Agent 创建接口

### 3.1 核心 API

```go
import "github.com/zhucl121/langchain-go/core/agents"

ca, err := agents.CreateUnifiedAgent(agents.UnifiedAgentConfig{
    Preset:       agents.PresetToolCalling,  // 切换预设即可改变策略
    Model:        llm,
    Tools:        myTools,
    SystemPrompt: "你是一个专业助手",
    MaxSteps:     15,
})
result, _ := ca.Run(ctx, "你的问题")
```

### 3.2 预设类型

```go
// 通用推理（逐步思考）
agents.PresetReAct

// 工具密集型（原生函数调用，推荐用于有大量工具的场景）
agents.PresetToolCalling

// 复杂多步任务（先规划再执行）
agents.PresetPlanExecute

// 复合查询（递归分解）
agents.PresetSelfAsk

// 多轮对话（带记忆管理）
agents.PresetConversationalV2
```

### 3.3 函数式选项 API

```go
// NewReActAgentV2 - ReAct Agent
ca, _ := agents.NewReActAgentV2(llm, tools,
    agents.WithUnifiedSystemPrompt("你是 Go 专家"),
    agents.WithUnifiedMaxSteps(20),
    agents.WithUnifiedVerbose(true),
)

// NewToolCallingAgentV2 - Tool Calling Agent
ca, _ := agents.NewToolCallingAgentV2(llm, tools,
    agents.WithUnifiedMiddleware(myMiddleware),
)

// NewMemoryAgentV2 - 带记忆的对话 Agent
memory := agents.NewInMemoryConversationMemory()
ca, _ := agents.NewMemoryAgentV2(llm, nil,
    agents.WithUnifiedMemory(memory),
)
```

### 3.4 多轮对话记忆

```go
memory := agents.NewInMemoryConversationMemory()

ca, _ := agents.CreateUnifiedAgent(agents.UnifiedAgentConfig{
    Preset: agents.PresetConversationalV2,
    Model:  llm,
    Memory: memory,
})

// RunWithMemory 自动加载/保存对话历史
result1, _ := ca.RunWithMemory(ctx, "Go 有哪些特点？")
result2, _ := ca.RunWithMemory(ctx, "继续详细说明")  // 感知第一轮上下文
```

### 3.5 与 ModelHooks 集成

```go
hookChain := middleware.NewHookChain(
    middleware.NewSummaryHook(2000, nil, 5),       // 历史摘要（防 context 膨胀）
    middleware.NewPIIRedactHook(middleware.DefaultPIIConfig()),  // PII 自动脱敏
)

ca, _ := agents.CreateUnifiedAgent(agents.UnifiedAgentConfig{
    Preset:     agents.PresetReAct,
    Model:      llm,
    ModelHooks: hookChain,
})
```

### 3.6 内置弹性配置

```go
ca, _ := agents.CreateUnifiedAgent(agents.UnifiedAgentConfig{
    Preset: agents.PresetToolCalling,
    Model:  llm,
    Resilience: &agents.ResilienceConfig{
        CircuitBreaker: agents.CircuitBreakerConfig{
            Name:             "llm-api",
            FailureThreshold: 5,
            SuccessThreshold: 2,
            Timeout:          30 * time.Second,
        },
        Bulkhead: agents.BulkheadConfig{
            Name:          "llm-api",
            MaxConcurrent: 10,
            MaxWaitTime:   5 * time.Second,
        },
    },
})
```

## 4. LangGraph 图能力增强

### 4.1 节点级缓存（Node-Level Caching）

避免相同输入重复调用 LLM，节省成本。

```go
import "github.com/zhucl121/langchain-go/graph/node"

// 创建带缓存的节点
cachedNode := node.NewCachedFunctionNode("expensive-node", myNodeFn,
    node.NodeCacheConfig{
        Enabled:    true,
        TTL:        10 * time.Minute,
        MaxEntries: 100,
        // 自定义缓存键（默认用输入状态的 SHA256 哈希）
        KeyFunc: func(state any) (string, error) {
            s := state.(MyState)
            return s.UserID + ":" + s.Query, nil
        },
    },
)

// 链式写法（在已有节点上添加缓存）
existingNode := node.NewFunctionNode("my-node", myFn)
cachedNode = existingNode.WithNodeCache(node.NodeCacheConfig{
    Enabled: true,
    TTL:     5 * time.Minute,
})
```

### 4.2 延迟节点 / Map-Reduce（Deferred Nodes）

等待所有并行分支完成后聚合，对标 LangGraph Deferred Nodes。

```go
import "github.com/zhucl121/langchain-go/graph/node"

// 声明需要等待的上游分支
deferredNode := node.NewDeferredFunctionNode("aggregator", aggregateFn,
    []string{"branch-a", "branch-b", "branch-c"},  // 等待这3个分支
    node.DeferredNodeConfig{
        Timeout:     30 * time.Second,
        FailFast:    false,           // 某分支失败不影响其他分支
        MinBranches: 2,               // 至少 2 个分支完成才聚合
    },
)

// MapReduceRunner 便捷封装
runner := node.NewMapReduceRunner[MyState]()
result, err := runner.Run(ctx, initialState,
    map[string]node.NodeFunc[MyState]{
        "worker-1": func(ctx context.Context, s MyState) (MyState, error) { /* ... */ },
        "worker-2": func(ctx context.Context, s MyState) (MyState, error) { /* ... */ },
    },
    func(ctx context.Context, s MyState) (MyState, error) { /* reduce 函数 */ },
)
```

### 4.3 可恢复流（Resumable Streams）

网络中断后自动续传，不丢失任何 token。

```go
import "github.com/zhucl121/langchain-go/graph/streaming"

storage := streaming.NewInMemoryStreamStorage(streaming.InMemoryConfig{
    TTL: 1 * time.Hour,
})

stream := streaming.NewResumableStream(streaming.ResumableStreamConfig{
    StreamID: "stream-" + threadID,
    Storage:  storage,
})

// 启动流
eventCh, _ := stream.Start(ctx, producerFn)

// 客户端断线重连后，从断点续传
eventCh, _ = stream.Resume(ctx, lastReceivedEventID)
for event := range eventCh {
    fmt.Printf("[%d] %s: %v\n", event.ID, event.Type, event.Data)
}
```

### 4.4 LangGraph Store（跨会话存储）

在 StateGraph 节点间共享数据，跨会话持久化。

```go
import "github.com/zhucl121/langchain-go/graph/store"

// 创建存储（生产替换为 Redis/PostgreSQL）
s := store.NewInMemoryStore()

// 注入到 context，在节点中访问
ctx = store.WithStore(ctx, s)

// 在图节点内
func myNode(ctx context.Context, state MyState) (MyState, error) {
    s, _ := store.GetStore(ctx)
    
    // 命名空间组织数据
    s.Put(ctx, []string{"users", state.UserID}, "profile", userData)
    item, _ := s.Get(ctx, []string{"users", state.UserID}, "profile")
    
    return state, nil
}
```

## 5. 可靠结构化输出（Trustcall）

### 5.1 基本用法

```go
import "github.com/zhucl121/langchain-go/core/output"

type UserProfile struct {
    Name  string `json:"name"  validate:"required"`
    Email string `json:"email"`
    Age   int    `json:"age"`
}

// 创建可靠提取器
extractor := output.NewReliableExtractor[UserProfile](
    llmCaller,  // func(ctx, messages) (string, error)
    output.DefaultReliableExtractorConfig(),
)

// 提取（自动重试 + JSON Patch 修复）
result, err := extractor.Extract(ctx, "用户叫 Alice，邮箱 alice@test.com，28岁")
if err == nil {
    fmt.Println(result.Value.Name)    // Alice
    fmt.Println(result.Attempts)      // 尝试次数
    fmt.Println(result.UsedPatch)     // 是否使用了 JSON Patch 修复
}
```

### 5.2 JSON Patch 修复原理

```
第1次调用 LLM → 返回有问题的 JSON（如缺少字段）
                  ↓ 验证失败
第2次调用 LLM → 只传 Patch 提示（"请修复 /age 字段"）
              → 返回 JSON Patch 数组（[{"op":"add","path":"/age","value":28}]）
                  ↓ 应用 Patch
              → 完整 JSON（低成本修复，不用重新生成）
```

### 5.3 自定义验证

```go
config := output.DefaultReliableExtractorConfig()
config.MaxRetries = 5
config.ValidateFunc = func(v any) error {
    profile := v.(*UserProfile)
    if profile.Age < 0 || profile.Age > 150 {
        return fmt.Errorf("age %d is invalid", profile.Age)
    }
    if !strings.Contains(profile.Email, "@") {
        return fmt.Errorf("email %s is invalid", profile.Email)
    }
    return nil
}
```

### 5.4 推理轨迹（ReasoningTracer）

```go
tracer := output.NewReasoningTracer()

tracer.AddThought("分析用户需求")
result, _ := searchTool(query)
tracer.AddToolCall("search", query, result, nil, elapsed)
tracer.AddThought("整合搜索结果，生成回答")

trace := tracer.Finish()
fmt.Println(trace.Summary())

// 转换为 ContentBlock（与 LangChain 1.0 Standard Content Blocks 互操作）
block := tracer.ToContentBlock()
// block.Type == types.ContentBlockThinking
```

## 6. 生产级容错机制

### 6.1 Circuit Breaker（熔断器）

防止连续失败导致级联故障。

```go
import "github.com/zhucl121/langchain-go/core/agents"

cb := agents.NewCircuitBreaker(agents.CircuitBreakerConfig{
    Name:             "openai-api",
    FailureThreshold: 5,            // 连续5次失败触发熔断
    SuccessThreshold: 2,            // 半开状态下连续2次成功恢复
    Timeout:          30 * time.Second,  // 熔断持续时间
    OnStateChange: func(from, to agents.CircuitState) {
        log.Printf("Circuit: %s -> %s", from, to)
    },
})

// 包装调用
result, err := cb.Execute(ctx, func(ctx context.Context) (any, error) {
    return llm.Invoke(ctx, messages)
})
if errors.Is(err, agents.ErrCircuitOpen) {
    // 熔断器打开，快速失败
}
```

### 6.2 Bulkhead（舱壁）

限制并发数，防止某个 Agent 耗尽所有资源。

```go
bh := agents.NewBulkhead(agents.BulkheadConfig{
    Name:          "agent-pool",
    MaxConcurrent: 10,              // 最多 10 个并发请求
    MaxWaitTime:   5 * time.Second, // 等待超时
})

result, err := bh.Execute(ctx, myAgentCall)
if errors.Is(err, agents.ErrBulkheadFull) {
    // 已达最大并发，拒绝请求
}
```

### 6.3 ResilienceWrapper（组合用法）

```go
wrapper := agents.NewResilienceWrapper("llm-api", agents.ResilienceConfig{
    CircuitBreaker: agents.DefaultCircuitBreakerConfig("llm-api"),
    Bulkhead: agents.BulkheadConfig{
        Name: "llm-api", MaxConcurrent: 10,
    },
})

result, err := wrapper.Execute(ctx, myFn)
```

## 7. Pre/Post Model Hooks

在 LLM 调用前后自动执行，实现切面式处理。

### 7.1 内置 Hook

```go
import "github.com/zhucl121/langchain-go/core/middleware"

// 历史摘要 Hook（防止 context 窗口溢出）
summaryHook := middleware.NewSummaryHook(
    2000,  // 超过 2000 token 时触发摘要
    nil,   // 使用默认截断函数（可替换为 LLM 摘要）
    5,     // 保留最近 5 条消息
)

// PII 脱敏 Hook（自动隐藏邮箱、手机等敏感信息）
piiHook := middleware.NewPIIRedactHook(middleware.PIIConfig{
    RedactInput:  true,  // 脱敏输入消息
    RedactOutput: true,  // 脱敏 LLM 响应
})

// 护栏 Hook（内容安全）
guardrailHook := middleware.NewGuardrailHook(middleware.GuardrailConfig{
    InputRules: []middleware.GuardrailRule{
        {Pattern: "恶意关键词", Action: middleware.GuardrailBlock},
    },
})

// 速率限制 Hook
rateLimitHook := middleware.NewRateLimitHook(10, time.Minute) // 每分钟10次
```

### 7.2 组合 Hook 链

```go
hookChain := middleware.NewHookChain(
    summaryHook,
    piiHook,
    guardrailHook,
    rateLimitHook,
)

// Hook 在每次 LLM 调用时按顺序执行
msgs, err := hookChain.BeforeModel(ctx, inputMessages)  // 调用前
resp, err  := hookChain.AfterModel(ctx, response)        // 调用后
```

### 7.3 自定义 Hook

```go
type MyAuditHook struct{}

func (h *MyAuditHook) Name() string { return "audit" }

func (h *MyAuditHook) BeforeModel(ctx context.Context, msgs []types.Message) ([]types.Message, error) {
    log.Printf("LLM call: %d messages", len(msgs))
    return msgs, nil
}

func (h *MyAuditHook) AfterModel(ctx context.Context, resp *types.Message) (*types.Message, error) {
    log.Printf("LLM response: %d chars", len(resp.Content))
    return resp, nil
}
```

## 8. 从 v0.6.x 升级

### 8.1 无需迁移

所有 v0.6.x API 保持不变，直接升级：

```bash
go get github.com/zhucl121/langchain-go@v0.7.0
```

### 8.2 建议迁移（可选）

**Agent 创建方式**（可选，旧版仍可用）：

```go
// 旧版（v0.6.x，仍有效）
agent := agents.CreateReActAgent(llm, tools, agents.WithMaxSteps(10))

// 新版（v0.7.0，推荐）
ca, _ := agents.CreateUnifiedAgent(agents.UnifiedAgentConfig{
    Preset:   agents.PresetReAct,
    Model:    llm,
    Tools:    tools,
    MaxSteps: 10,
})
result, _ := ca.Run(ctx, input)
```

### 8.3 新增依赖

v0.7.0 无新增外部依赖，保持零依赖增长。
